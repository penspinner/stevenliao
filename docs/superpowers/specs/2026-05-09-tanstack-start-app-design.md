# TanStack Start App Design

Add a third app variant (`apps/app-tanstack-react-start`) that renders pages from the shared `personal-site` package, alongside the existing Next.js and React Router apps.

## Decisions

- **Route pattern**: Single-file routes (one file per page), matching the React Router app's approach. No separate server/client component files.
- **App directory**: `src/` convention (TanStack Start's default). Routes at `src/routes/`.
- **Deployment**: Vercel, alongside the other two apps.
- **verbatimModuleSyntax**: Disabled for this app only, per TanStack Start docs recommendation (can cause server bundles to leak into client bundles).

## Route details

### `__root.tsx` — Root layout

Follows the same composition pattern as the React Router app's `root.tsx`:

- `createRootRoute` with `head()` for meta charset/viewport, `links()` for CSS/fonts, and a `loader` for color scheme (read from cookie).
- `RootComponent` renders:
  - `Document` from `personal-site` (server-safe — wraps `<html>`, injects color scheme script)
  - `Layout` from `personal-site/client` (client component with `framer-motion` — header, nav, footer)
  - TanStack Router's `<HeadContent>`, `<Scripts>`, `<Outlet>`
- Adapter props on `Layout`:
  - `linkRender` → `<Link>` from `@tanstack/react-router` (with `preload="intent"`)
  - `colorSchemeToggleRender` → wraps with a `<form>` that POSTs to `/color-scheme` via `createServerFn`
  - `avatarImg` → plain `<img>` element
  - `currentPathname` → from `useRouter().state.location.pathname`
- Color scheme: read server-side in loader, optimistic client-side via fetcher to `/color-scheme`.
- Error boundary: catches route errors, renders `RootErrorBoundary` or `RootNotFound` from `personal-site` depending on 404 status.
- Progress bar: Uses `@badrap/bar-of-progress` tied to `useRouter().state.isLoading`, matching the React Router app's approach.

### Page routes (`index.tsx`, `about.tsx`, `articles.tsx`, `projects.tsx`, `uses.tsx`)

Each uses `createFileRoute` with:

- `loader` for data fetching (index and articles call `getArticles` from `personal-site`; others are static).
- `head()` for page-specific title/description meta imported from `personal-site` (e.g., `indexTitle`, `indexDescription`).
- `component` that renders the page component from `personal-site` with appropriate props (hardcoded content for projects, roles, photos — matching the React Router app).

### `color-scheme.ts`

POST route using `createServerFn` that sets/clears the `color-scheme` cookie. Validates input to `'dark' | 'light' | 'system'`. No separate route file — handled as a server function called from the root route's form.

## CSS

Vite-based Tailwind v4 via `@tailwindcss/vite` plugin (same as React Router app). Single `src/tailwind.css`:

```css
@import 'personal-site/tailwind.css';
```

Font declarations (Inter) are handled via a `<link>` in the root route's `head()` or `links()`, loading from Google Fonts.

## vite.config.ts

```ts
import localesPlugin from '@react-aria/optimize-locales-plugin'
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import tailwindcss from '@tailwindcss/vite'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    tailwindcss(),
    tanstackStart(),
    react(), // must come after tanstackStart()
    { ...localesPlugin.vite({ locales: [] }), enforce: 'pre' },
  ],
  ssr: {
    external: ['personal-site'],
  },
})
```

Same `ssr.external: ['personal-site']` workaround as the React Router app — prevents Vite's SSR module runner from returning `undefined` for named exports of the workspace package.

## tsconfig.json

Extends `tsconfig/base.json`. Overrides:

- `jsx: "react-jsx"`
- `lib: ["DOM", "DOM.Iterable", "ESNext"]`
- `verbatimModuleSyntax: false` (per TanStack Start docs — prevents server bundle leakage)
- Includes `src/**` and TanStack Start's generated types path

## Turborepo integration

Add to `turbo.json` — `build` task with `dependsOn: ["^build"]`, outputs including `dist/**`. Add `dev` and `watch` tasks (cached: false, persistent: true). Add root `dev:trs` script:

```sh
turbo run dev watch --filter app-tanstack-react-start --filter personal-site
```

TanStack Start provides a built-in Vercel adapter. During implementation, check the exact adapter API for v1.167.65 and wire it into `vite.config.ts`. Fallback: TanStack Start's node preset works on Vercel.

## Non-goals / out of scope

- i18n / locale detection (the React Router app has `I18nProvider` + `getLocalizationScript`; not needed here)
- Bot-aware streaming (not needed for a learning variant)
- Copying/symlinking shared images — reference local `/images/` paths, matching the React Router app's approach
